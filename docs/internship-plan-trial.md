# 「第一份实习 7 天计划」试用手册

这份手册用于小样本、有人在场的学生试用。目标不是证明产品有效，而是尽快看清两件事：**学生愿不愿意把计划留下来，以及会不会真的完成第一项。**

## 一、先明确边界

- 提醒目前只在本站页面打开时出现，并使用浏览器通知；关闭浏览器后不会推送。真正的离线提醒需要接入微信、短信或邮件通道，当前未接入。
- 未配置真实模型时，计划是内置模板，页面会明确标注「当前未接入真实模型」。试用前请确认后端已配置模型，否则不要用「个性化计划」对外描述。
- 判断方法：生成一份计划，若页面出现那行模板提示，或统计接口返回 `source: "template"`，说明模型没生效（常见原因是 key 失效返回 401，此时系统会自动降级而不是报错）。
- 不要把 5～8 人的结果写成「转化率已达标」。样本小，只用于发现问题。

## 二、开工前自检（3 分钟）

按顺序过一遍，任何一项不过就先别约学生：

1. **库对不对**：`backend/.env` 的 `DATABASE_URL` 指向正式库，而不是临时文件库。在 `backend` 目录跑 `python scripts/trial_report.py`，能正常输出表格即说明连得上。
2. **模型通不通**：随便生成一份计划，看有没有模板提示。有就先去换 `LLM_API_KEY`。
3. **库干不干净**：同一条统计命令底部会写「已排除 N 个自测账号」。若 `N` 大于 0，说明库里有联调账号，不影响统计（默认已剔除），但正式收数据前建议按第九节清掉。

## 三、样本与准备

- 6～8 名大二、大三学生，正在找第一份实习，方向分散在产品、运营、开发中至少两类。
- 每人一台电脑或手机，独立账号，避免共用账号污染数据。
- 注册成功后会自动登录并直接进入站内，不需要再手动登录一次；如果看到登录页，说明自动登录失败，记一笔。
- 准备一句统一的开场：「这是一个帮你把找实习拆成 7 天的工具，今天想看看它哪里不好用，不用客气。」

## 四、30 分钟流程

1. **不引导地打开首页（3 分钟）**：只观察学生第一眼看哪里、会不会自己找到提问框。记录他说的第一句话。
2. **让他自己提一个问题（7 分钟）**：不提示快捷问题。观察是否愿意输入真实困惑。
3. **注册并进入计划页（5 分钟）**：不主动说「去注册」。观察注册表单是否劝退（密码要求、姓名是否愿意填）。进入计划页后只在他卡住时提示「右边有生成计划的入口」，记录方向、年级、每周时间是否填写顺畅。
4. **完成第一项（8 分钟）**：请他挑一项现在就能做的，真的做完再勾选。观察反馈文案是否让他知道下一步。
5. **开启提醒（2 分钟）**：请他设置提醒时间，问一句「你觉得它明天会怎么提醒你」。
6. **访谈（5 分钟）**：见下方问题清单。

## 五、访谈问题

- 刚才那 7 天里，哪一项你最可能真的去做？哪一项最像凑数？
- 勾选完成后那句话，对你继续做下一项有帮助吗？
- 如果明天只收到一句提醒，你希望它说什么？
- 你愿意把这份计划留在账号里，下周再回来吗？为什么？
- 如果这项服务收费，你会在哪一步犹豫？

## 七、指标口径

- **保存率** = 生成计划的用户数 ÷ 打开过计划页的用户数。`plan_opened` 每人每天只记一次。
- **首项完成率** = 完成至少一项的用户数 ÷ 生成计划的用户数。
- **全计划完成率** = 完成 7 项的用户数 ÷ 生成计划的用户数。
- **生成到首项完成中位时长**：用于判断任务是否「当天可做」。

初版目标线（仅作内部判断，不对外）：保存率 ≥ 60%，首项完成率 ≥ 40%。低于目标线时，先改任务粒度和入口，不要先加功能。

## 八、导出统计

在 `backend` 目录执行（只读，不写库）：

```powershell
python scripts/trial_report.py
```

默认读取 `.env` 的 `DATABASE_URL`（正式库）。需要临时指向别的库时用 `--db-url`：

```powershell
python scripts/trial_report.py --db-url "sqlite+aiosqlite:///../app.db"
```

输出包含打开、生成、首项完成、全部完成、提醒开启人数，以及保存率、首项完成率、全计划完成率、中位时长。

**关于自测账号**：注册邮箱以 `@example.com`、`@example.test`、`@test.local` 结尾，或以 `e2e`、`probe` 开头的账号，默认会被排除，底部会写「已排除 N 个自测账号」。需要连自测数据一起看时：

```powershell
python scripts/trial_report.py --include-test-accounts
```

此时输出会额外提示「当前包含自测账号，数字不可当作试用结果」。

## 九、试用后怎么处理数据

- 学生账号与计划属于个人信息。导出统计只保留聚合数字，不要把学生原话、邮箱和计划内容写进对外材料。
- 试用结束如需删除数据，按账号删除 `internship_plans`、`internship_plan_tasks`、`plan_reminders`、`plan_events` 中对应记录。
- 清掉联调产生的自测账号（按外键顺序执行，先子表后主表）。下面以 `%@example.com` 为例；若自测账号用了 `e2e`、`probe` 前缀，把条件换成 `email LIKE 'e2e%' OR email LIKE 'probe%'`：

```sql
DELETE FROM plan_events      WHERE user_id IN (SELECT id FROM users WHERE email LIKE '%@example.com');
DELETE FROM plan_reminders   WHERE user_id IN (SELECT id FROM users WHERE email LIKE '%@example.com');
DELETE FROM internship_plan_tasks
 WHERE plan_id IN (SELECT p.id FROM internship_plans p
                     JOIN users u ON u.id = p.user_id
                    WHERE u.email LIKE '%@example.com');
DELETE FROM internship_plans WHERE user_id IN (SELECT id FROM users WHERE email LIKE '%@example.com');
DELETE FROM users            WHERE email LIKE '%@example.com';
```
